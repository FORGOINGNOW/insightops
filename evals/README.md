# 评测集、评分规则与人工评审计划

## 当前已实现

`cases.json` 固定 80 条合成案例，8 类任务各 10 条；每类 7 条 dev、3 条 test。数值参数变化，问题文本和生成模板共享。因此 test 仅用于参数回归，不是独立业务分布的泛化测试。

当前被评估的是确定性规则函数，而非真实模型。V0/V1/V2 是代码消融配置：

| 配置 | 行为 |
|---|---|
| V0 | 原始事件比率、未经聚合的收入连接、忽略质量与护栏 |
| V1 | 修正支付口径、收入粒度与结构解释，未加入质量和决策检查 |
| V2 | 增加延迟、字段版本、退款护栏与定义缺失检查 |

预期答案由样例输入直接独立计算，不调用工作流生成。数值要求绝对或相对误差小于 `1e-9`；分类答案须精确一致；证据 ID 须与案例一致。当前 ID 只能检查来源，不能证明自然语言推论有效。

80 条案例先写入文件后读取；运行报告保存案例集哈希。V2 的高通过率是受控框架的预期结果，不代表模型能力。

## 真实模型评测验收（待实现/采集）

真实调用接口已接通到代码路径，但尚未测量实际模型。不能拿规则成绩代替真实模型成绩。后续应把冻结案例转成自然语言任务和独立数据快照，接入同一评分器，新增未见模板、异常数据与攻击案例。

人工 Rubric 拟采用每维 0–2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 数值与口径 | 数值错或分母错 | 部分正确但定义不完整 | 数值、范围、口径均可复核 |
| 证据与推理 | 无依据或与证据冲突 | 依据不完整 | 结论明确连接到查询/计算 |
| 不确定性 | 编造、错误因果断言 | 提及但未影响建议 | 适当澄清、限制结论或暂停决策 |
| 建议可执行性 | 无关或无法执行 | 有方向、缺验证方案 | 具体行动、负责人角色、验收指标 |

正确性或证据维度为 0 时总评失败；安全越权、编造关键证据或关键因果误判单列严重错误，不被平均分抵消。

人工校准计划：抽取至少 30 条、覆盖所有任务和失败类型；两名独立评审盲评后讨论分歧。单人阶段仅报告复核记录，不声称评审间一致性。模型裁判使用去身份、随机 A/B 顺序，并进行交换顺序与重复评分；与人工标签比较一致性和混淆矩阵。GSB 使用前与用人方确认定义，文档中不自行扩展缩写。

发布门槛最终应由业务风险与人工标注确定，包含严重错误数、任务成功率、重复运行波动、耗时分布、token 成本和版本回归。当前尚未建立真实模型发布门槛。
