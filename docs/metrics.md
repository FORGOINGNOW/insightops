# 指标字典与数据合同

## 数据来源与粒度

全部数据通过 `data.py` 的固定种子生成，无第三方数据授权或真实用户信息。before 为 2026-09-01 至 09-07，after 为 2026-10-01 至 10-07；只是两个样例观察窗口，不代表整月。

| 表 | 粒度/主键 | 数据合同 |
|---|---|---|
| users | 一个用户/user_id | 渠道、设备、新老属性属于样例固定属性 |
| assignments | 一个分配用户/user_id | 分配 A/B 标签；业务诊断不据此解释因果 |
| sessions | 一个会话/session_id | 本样例每用户一个会话，真实多会话须考虑用户内相关性 |
| orders | 一个支付订单/order_id | 本样例每会话最多一个支付订单；金额单位为分 |
| order_items | 一个订单行/order_id,line_no | 每订单两行，行金额合计应等于订单金额 |
| events | 一次收到的上报/event_id | logical_id 标识同一业务事件，允许重复收到 |
| session_facts | 一个会话/session_id | 以订单作为支付事实来源，不依赖埋点完整性 |

## 核心指标

| 指标 | 分子/分母 | 口径与局限 |
|---|---|---|
| 会话支付转化率 | 存在支付订单的会话 / 全部会话 | 分母包含未支付会话；订单按会话发生期归属 |
| 原始埋点转化率 | 已收到的 payment 行 / 已收到的 view 行 | 故意保留的错误基线，不能用于决策 |
| 标准化转化率 | Σ before 渠道会话占比 × 当期渠道转化率 | 描述性分解；不等于因果控制 |
| 支付收入 | 支付订单 amount_cents 之和 | 毛收入，未扣退款；明细须预先聚合 |
| 重复事件数 | 收到事件数 − 不同 logical_id 数 | 当前以快照全部上报计算 |
| 延迟支付数 | received_at 超过截止点的 payment 数 | 数据中有完整后续到达记录；实际监控只能使用当时可得数据 |
| 缺失支付事件 | 有支付订单但整个快照无 payment 的会话数 | 与截止点尚未到达的事件分开计算 |

所有时间为无时区 ISO 样例时间，视为 UTC；仅用于可复现合成样例，生产接入应使用明确时区的时间类型。分析 cutoff 为 `2026-10-15T00:00:00`。当前质量计数使用完整快照，不能伪装为历史实时可见信息。

## 质量验收

1. 用户/会话/订单关联完整，订单金额为正。
2. 订单收入等于明细收入，也等于独立生成账本。
3. 分渠道的会话与支付数等于生成账本。
4. 故障计数与生成阶段账本一致。
5. 工作流开始前验证数据清单中的文件 SHA-256，防止快照混用。

异常被检测到不代表数据适合所有用途。原始埋点存在故障时，报告应显式提示并使用定义完整的订单事实口径。真实接入还需要确认订单状态、撤单、跨期支付与退款成熟窗口。
