# 五分钟项目讲解稿

## 0:00–0:40：问题和决策

转化下降后，先确认是指标问题、流量结构变化，还是产品效果。项目把数据核对、统计验证和 AI 报告串起来，让每个结论有可追溯证据。

## 0:40–1:30：合成案例可验证真值

展示 17% 到 8% 的总体变化、稳定的渠道内转化、固定权重后的 17%。说明为何观察性分解不能证明产品因果效果。再展示重复、迟到、缺失事件和错误连接导致的金额翻倍。

## 1:30–2:20：真实数据中的取舍

打开 UCI 报告，展示缺失客户 ID 删除会遗漏金额，以及为什么保留候选重复、将未成熟复购指标留空。真实数据只有发票，没有访问分母，所以不计算转化率。

## 2:20–3:00：统计与工程

模拟实验中主指标改善、退款护栏恶化，触发暂停建议。MongoDB 百万条事件聚合的结果与 SQL 对账，再展示覆盖索引的执行计划。性能数字只对应本机合成基准。

## 3:00–4:20：真实模型和失败分析

打开实际运行的挑战评测摘要和一条失败原文，区分结构化评分、数值核验、门禁拦截和人工判断。V1/V2 是整体配置对比，不能把差异全部归因于提示词。

## 4:20–5:00：工程验收与局限

展示测试与 GitHub Actions。明确指出仍需独立评审、真实业务接入、成本价格表和更广挑战集。说明下一次迭代将优先修复哪个实际失败，而不是添加无测量依据的组件。

简历可写已完成的公开数据分析、可复现诊断、统计实验实现和本机 MongoDB 基准。模型评测数字必须同时写明模型、样本数和组件范围；不声称真实增长收益或多人协作经历。
