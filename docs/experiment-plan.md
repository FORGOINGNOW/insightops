# 模拟实验预设方案

此文档描述生成前定义的分析规则。当前没有真实流量，也没有实际预注册。

- 目标：判断新版结账流程是否改善用户支付，同时控制退款损害。
- 随机化单位：用户。按 1:1 随机分配，采用 ITT（按分配组）分析。
- 主指标：完成支付用户 / 分配用户。
- 护栏：固定成熟窗口内发生退款的用户 / 分配用户。此分母避免仅对处理后支付者筛选带来的解释问题。
- 主指标双侧 α=0.05，设计基线 10%，绝对 MDE=1.5 个百分点，目标功效 80%。代码输出正态近似的每组样本量。
- 观察方案：模拟固定总样本 20,000 人、无中途窥探；实际周期需结合流量和完整退款观察窗口确定。
- 数据验收：一个分配记录/用户；实际流量还必须检查曝光、跨组污染和丢失。本模拟未实现真实采集链路。
- SRM：二项精确检验，阈值 0.001；触发则停止解释处理效果。
- 主指标：双样本比例 z 检验，报告绝对效果与 95% 正态近似 CI；稀疏或边界数据需更换区间方法。
- 护栏容忍度：退款用户比例最多增加 0.2 个百分点。若其 95% CI 下界超过容忍度，判为明确损害，暂停上线。
- 其他情况：当前实现只给出“继续审查”而不会自动批准上线。完整上线规则还需要证明主指标收益与护栏的可接受性。
- 分层：organic/paid 预设用于解释，标注为探索性，不据此进行额外确认性宣称。

当前生成机制故意使 B 转化提升，同时退款概率增加，以验证“主指标显著不等于可以上线”。`skew=True` 额外制造 60:40 分配，验证 SRM 拦截。

观察性渠道分析与此随机实验是独立数据流程，不把两者的结果拼成同一个真实产品故事。
