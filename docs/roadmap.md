# 迭代路线与交付边界

## v0.1：可运行的合成基线

- 数据生成、独立账本、SQLite 建模与质量诊断。
- 分层及渠道结构分解、收入对账。
- 独立模拟 A/B、SRM 与护栏。
- 冻结规则评测集、声明核验、运行溯源与 CI。
- MongoDB 性能与对账脚本、可选模型 API 路径。

## v0.2：真实证据优先

1. 实际运行 MongoDB，保存执行计划和环境参数；验证较大规模数据，避免仅展示微型基准。
2. 选择授权清晰的公开交易数据，新增真实清洗案例；与合成实验分开报告。
3. 配置真实模型，建立真实工作流任务评分、token/耗时记录和失败分类。
4. 增加独立模板与数据分布的挑战集，人工复核至少 30 条。
5. 编写可追溯的版本改进报告，记录没有改善的尝试。

## v0.3：有测量依据后再扩展

- 加入指标文档检索，评估有/无 RAG 的增益与错误类型。
- 如需外部工具复用，再实现受限 MCP 接口。
- 建立人工与 LLM 裁判校准、重复评分稳定性和位置偏差实验。
- 仅当确定性流程确有编排瓶颈时考虑多 Agent。
- 微调需要稳定任务、授权数据及可靠评测后再讨论。

## 公开展示原则

不把合成收益写成真实业务收益；不把脚本存在写成完成实测；不把规则回归写成 LLM 评分。每条简历数字必须能追溯至提交版本、运行参数、数据清单和报告。
