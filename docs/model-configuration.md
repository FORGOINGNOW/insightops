# 模型配置与可核验实测

在仓库目录执行 `python -m insightops.cli configure`，依次输入接口根地址、服务商的确切模型标识和 API Key。根地址不要包含 `/chat/completions`。密钥输入隐藏；配置保存于本地 `.env`，不会提交到 Git。`.env` 是本地明文配置，不是加密凭证库，勿共享或截图。

`configure --check` 只检查本地设置是否齐全，不证明凭证有效。`configure --probe` 使用认证读取 `/models`，输出 HTTP 状态和可用模型标识，不发送生成请求。部分兼容服务不支持模型列表，这种情况下需参照其实际接口说明。

环境变量 `INSIGHTOPS_API_KEY`、`INSIGHTOPS_MODEL`、`INSIGHTOPS_BASE_URL` 的优先级高于 `.env`。不要把凭证写入命令行、GitHub Actions 配置或报告。

## 请求控制

- `challenge-eval` 默认 dry run，明确带 `--live` 才调用服务。
- 默认最多 12 次请求；完整两个配置×24 场景需要显式 `--max-requests 48`。
- 认证、余额、速率、错误模型等不可继续的 HTTP 错误会停止，已完成记录仍保存。
- 不自动重试、不自动切换模型，避免隐性增加费用或混淆实验配置。
- 记录实际 token usage；没有经确认的价格表时不计算金额成本。
- 记录接口异常类型和安全的 HTTP 状态，不保存上游异常正文。

## 评测边界

真实模型对同一份固定证据完成报告与决策。参考答案不进入模型请求，但 V2 会收到由证据合同推导的确定性约束，这是系统设计的一部分。数据并非隐藏的代表性生产分布，不能把通过率称为通用分析准确率。

V1/V2 同时改变提示词和门禁，因此整体对比不能单独归因于提示词。后续需要独立消融、重复采样和新任务集。

数字引用正确不代表摘要语义正确；严格 decision 标签评分也可能把语义接近的拒答判为失败。保留原文并进行人工复核，不通过放宽答案键追求更高分。
